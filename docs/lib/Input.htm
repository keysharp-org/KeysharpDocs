Input Object

class Input extends Object

Describes one keyboard or mouse reported by the current input source. Instances come from Input.Devices.

This class is exported by the Ks module:

#Import Ks { Input }

Devices

Devices := Input.Devices

A read-only property returning a normal Array of Input objects for the current keyboards and mice. Each read returns a new list of new objects. A list already held by a script does not change when devices are connected or removed.

An empty Array means that no keyboard or mouse was listed. An unavailable inventory, denied access or enumeration failure throws an OSError. Array indexes are ordinal positions, unrelated to Id. Use Array.Filter to select devices by their properties; a selection can contain no devices, one device or several devices.

Device properties

All properties are read-only and contain the information completed when the descriptor was returned. Property reads do not query the device again. Missing text is an empty string; a missing number is 0. A descriptor keeps its values after the device disconnects.

PropertyDescription
IdAn opaque Integer identifying the device within its current input source, or 0 when unavailable. It is not an Array index or a permanent hardware identity. Values can change or be reused after reconnection, resume or a source restart. Identifiers from different sources need not be comparable.
Kind"Keyboard" or "Mouse".
NameThe name reported by the input source, when available. Names can repeat.
VendorIdThe numeric vendor identifier, or 0 when unavailable.
ProductIdThe numeric product identifier, or 0 when unavailable.
HardwareIdThe input source's hardware identity string, or an empty string when unavailable. Its format and persistence depend on the source. It may identify a model or interface rather than one physical unit.

A device can expose several interfaces or both kinds, so an entry is not necessarily one physical unit. Identical devices can share a name, vendor/product pair or hardware ID. No property is guaranteed to identify one unit permanently. Compare reported values when selecting a device; objects from separate reads are distinct descriptors.

Remarks

Windows

Lists the keyboard and mouse interfaces known to Windows Raw Input. Id contains the Raw Input device handle's value. Names and hardware identifiers come from system device metadata. VendorId and ProductId use native HID attributes when available; an ACPI identifier does not supply numeric USB vendor or product identifiers.

Linux

Id contains the keysharp-input device ID. Device information requires an available keysharp-input service and an existing Input Monitoring grant. Listing devices does not request a grant or initialize input forwarding. Client ABI 1.1 and a matching service can check an existing grant directly. With an older client or service, listing succeeds only if another authorized input operation has already given the current connection access to device information; otherwise it throws an OSError.

macOS

The implementation reads keyboard and mouse descriptions from IOKit HID services, using a supplied serial number as HardwareId. Id is 0. Runtime behavior on macOS is unverified.

Examples

Lists the reported keyboards.

#ErrorStdOut
#Warn All, StdOut
#Import Ks { Input }

for Device in Input.Devices.Filter((Device) => Device.Kind == "Keyboard")
    OutputDebug Device.Name ": " Device.HardwareId
