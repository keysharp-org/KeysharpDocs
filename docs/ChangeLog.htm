Recent Changes

This page summarizes the script-visible changes in recent Keysharp releases, so that a script written against an earlier version can be brought up to date. The release page holds the authoritative notes and the downloads for each version.

Note: Keysharp has not reached version 1.0. Behavior can change between releases, including in ways which require edits to existing scripts. Each release below lists its breaking changes first.

0.0.0.17

In development.

Breaking Changes

  • A value passed where a variable reference is expected must be one: a VarRef, or an object defining __Value (a virtual reference). Anything else — an ordinary object, a string, a number — throws a TypeError naming the parameter, where a Map or other object previously absorbed the output into a new __Value property that nothing read. This applies to every output parameter of a built-in and to a script function's own & parameters. IsSetRef is stricter still and requires an actual VarRef, since whether a variable has been assigned is not a question a stand-in answers.
  • The #Assembly*, #ConsoleApp and #HookMutexName directives were removed. Their settings are keys of the new #App block (Title, Name, ConsoleApp, HookMutexName, ...); each removed directive produces a compile-time error naming its replacement key. #SingleInstance, #NoTrayIcon and #ErrorStdOut remain their standalone directives and are not #App keys.
  • More Keysharp-only variables moved into the Ks module and must be imported: A_ClipboardTimeout, A_HotIfTimeout, A_InputLevel, A_IsPersistent, A_LoopKey, A_MaxThreadsBuffer, A_MaxThreadsPerHotkey, A_NewLine, A_PeekFrequency and A_Priority.
  • The Keysharp-only assembly-metadata variables were removed, and the App class carries those facts instead: A_AsmTitle, A_AsmDescription, A_AsmConfiguration, A_AsmCompany, A_AsmProduct, A_AsmCopyright, A_AsmTrademark and A_AsmVersion become App.Title, App.Description, App.Configuration, App.Company, App.Product, App.Copyright, App.Trademark and App.Version, with App.Name for the assembly identity. A_CommandLine becomes App.CommandLine. Reach the class with #Import Ks { App }, or with #Import Ks and then Ks.App.
  • A_KeysharpPath was removed. Use A_AhkPath, which it aliased.
  • A_AhkBuildVersion was removed with no replacement. Ks.A_KsVersion reports the engine build, and App.Version the application's own version.
  • A_HasExited was removed, and App.ExitReason != "" reports that an exit is under way. This is not a rename: A_HasExited became true only once teardown had finished, while App.ExitReason is non-empty from the moment the exit begins, including throughout the OnExit callbacks, where A_HasExited was false. A guard such as if !A_HasExited inside an OnExit callback therefore stops running if the name is substituted mechanically.
  • Reading an #App key which was never declared yields an empty string, in both compatibility modes. In v2.1 mode the removed variables instead returned an unset value, which raised as soon as it was used. App.Company != "" is the test for whether a key was declared; HasOwnProp is not, because it reports every property present.
  • The Keysharp-only screen variables A_WorkAreaWidth, A_WorkAreaHeight, A_TotalScreenWidth, A_TotalScreenHeight and A_ScreenScale were removed; the Monitor class carries those facts for every monitor rather than only the primary. Use Monitor.Primary.WorkArea.Width/.Height, Monitor.VirtualScreen.Width/.Height and Monitor.Primary.Scale. The AutoHotkey-standard A_ScreenWidth, A_ScreenHeight and A_ScreenDPI are unaffected — note A_ScreenDPI is the system's logical text-size DPI, not the panel density Monitor.Dpi reports. With no display attached the work-area replacements raise instead of yielding 0.
  • A_ThreadId was replaced by A_Thread, a Thread object. A_Thread.Id reads what it did.
  • On Linux and macOS, A_AppData and A_AppDataCommon name the platform's own configuration locations instead of the home directory and /usr/share. A_AppData reads $XDG_CONFIG_HOME or ~/.config on Linux and ~/Library/Application Support on macOS; A_AppDataCommon reads $XDG_CONFIG_DIRS or /etc/xdg on Linux and /Library/Application Support on macOS. A script which kept files under either variable on those platforms must move them. Windows is unaffected.
  • AES, CRC32, MD5, SHA1, SHA256, SHA384, SHA512 and SecureRandom are methods of the Crypt class rather than bare functions.
  • CopyImageToClipboard and IsClipboardEmpty were removed. Use Clipboard.Image and Clipboard.IsEmpty.
  • MonitorFromPoint and MonitorGetScale were removed. Use Monitor.FromPoint and Monitor.Scale. An out-of-range monitor number throws a ValueError instead of selecting the primary monitor.
  • Objects handed to a script name their members in PascalCase: a size is {Width, Height} and a position {X, Y}. The W and H properties of Monitor, Overlay and Highlight are likewise Width and Height.
  • Ks.JsonEncode and Ks.JsonDecode became Json.Encode and Json.Decode. A JSON null decodes to unset unless NullValue names a stand-in.
  • Assigning unset to a Map element removes it, and reading an absent element raises an UnsetItemError.
  • Exit takes only ExitCode; its thread-identifier parameter was removed. Use the Thread object to end another thread.
  • WinEvent's IsPaused property is named Paused.
  • Image.GetPixelData's BytesPerPixel defaults to 4 (RGBA), matching SetPixelData and Image.FromBuffer, so the three round-trip. A call which relied on the default to get 8-bit grayscale must pass 1 explicitly; the buffer is four times the size otherwise, and an OCR engine told bytes_per_pixel = 1 misreads it.
  • A hook's IsActive means is firing, so a paused hook reports 0 where it previously reported 1. A test of IsActive which meant "still registered" becomes Status != "Stopped", using the new Status property: "Active", "Paused" or "Stopped". Paused reports 0 on a stopped hook and ignores writes to one. This applies to WinEvent, whose global WinEvent.Paused makes every hook report "Paused", to ClipboardHook, and to the Monitor.OnChange subscription.
  • A stopped hook reports Count 0. WinEvent hooks and the Monitor.OnChange subscription previously kept reporting the budget they had left — -1 for an unlimited hook — after Stop(), so a Count = -1 test could not tell a live unlimited hook from a stopped one. ClipboardHook already reported 0.
  • A Clipboard.OnChange hook is no longer part of the OnClipboardChange handler chain. Its return value is discarded, where a non-zero return — including an incidental one such as the result of an Array.Push — previously stopped the OnClipboardChange callbacks registered after it. The hook's callback also runs on its own thread rather than inline on the notification, so a statement following a clipboard change may now run before the hook does. Both spellings still drive one native clipboard monitor.
  • LockRun(LockObject, Callback, Arguments*) was removed. Create a lock with lk := Lock() and hold it with Acquire/Release; the scoped form is ordinary script code. Only a Lock can be locked on, so an arbitrary object is no longer accepted.
  • A RealThread worker reports completion as a Task, and has two of them. Wait() was removed: it waited for the operating-system thread, which is Await(worker.Terminated), while Await(worker.Task) waits for the entry function and returns its value. Those differ for a worker which stays up to serve a timer or hotkey. ContinueWith(Callback, Arguments*) was removed; write worker.Task.Then(v => RealThread(Callback, Arguments*)). IsActive, IsSuccessful, IsFailed, IsCanceled and Result were removed; read IsAlive, or the Task's Status and Result. A worker's body error is delivered to whoever awaits its Task rather than reported on the worker.
  • Await no longer accepts a RealThread and raises a TypeError naming the two members to pass instead: worker.Task or worker.Terminated. The same applies to Task(Value), Task.WhenAll, Task.WhenAny, __Await() and work returned from a Then callback.
  • The read-only Visible property of Overlay and Highlight is named IsVisible, and the Granted property of the object RequestCapabilities returns is IsGranted. An Is prefix marks an observed state, and a plain Visible — as on Gui and Gui.Control — a settable one. The per-capability values are still the strings "Granted", "Denied", "NotApplicable" and "Unsupported".
  • An encoding name which cannot be resolved throws a ValueError instead of being substituted. This applies wherever an encoding is named, including FileEncoding, FileRead, StrGet and StrPut.
  • Parameters whose names were not valid identifiers were renamed so named arguments can address them: Part# to PartNumber, RootDir\Filename to RootDirFilename, ControlID-or-Pos to ControlOrPos and YYYYMMDDHH24MISS to Timestamp. Other built-in parameter names were corrected to match this documentation.
  • FuncObj is no longer a name; the function-object class is Func. InputObject likewise became InputHook.
  • Overlay construction takes either no arguments or a complete X, Y, Width, Height rectangle. Use Overlay.FromImage(Source) to construct one from an image.
  • An Overlay no longer duplicates Image drawing methods. Draw and read through its borrowed Canvas; copy the canvas before transforming or taking ownership of it.
  • Overlay.Update(Source, ...) became SetImage(Source, ...). BeginDraw/EndDraw are replaced by an explicit Present() after drawing, and Redraw passes its callback the replacement canvas rather than the overlay.
  • Image changes: DrawText and MeasureText take SetFont-style Options and FontName; MeasureText returns an object rather than writing ByRef; Opacity became Alpha; and Search, SearchAll and SearchPixel return a match object and take a flat region.
  • RichText is a member of the RichEdit control rather than of every GuiControl, and reading it returns the RTF document it always accepted on assignment, where it used to return the displayed plain text. Use Value for the plain text.
  • The WebBrowser control type is named WebView: MyGui.Add("WebView", Options, URL), MyGui.AddWebView(Options, URL) and the class Gui.WebView, in place of "WebBrowser", AddWebBrowser and Gui.WebBrowser.
  • InputHook.OnMouseMove reports deltas as (Hook, DX, DY) rather than positions.
  • A callback which requires more parameters than its registration site passes throws when registered rather than at each call. Declaring fewer is still allowed.
  • A callback is passed as a function object, never as a function's name in string form. SetTimer("MyFunc"), OnEvent("Click", "MyFunc"), Func("MyFunc") and every other such site now raise a TypeError; write SetTimer(MyFunc), or SetTimer(%"MyFunc"%) when the name is known only at run time. This matches AutoHotkey v2, which dropped function names in the same places. Func(Name, Obj) went with them; ObjBindMethod binds a method by name. A Gui built with an event sink is the one exception, and takes one of that sink's method names in OnEvent, OnNotify, OnCommand and OnMessage, as in AutoHotkey. Hotkey's Action and Hotstring's Replacement keep their own string meanings — an alt-tab action or hotkey name, and replacement text — and no longer look a string up as a function first.
  • Array.IndexOf throws an IndexError for an out of bounds StartIndex, as FindIndex already did. An empty array still returns 0.
  • OwnProps takes no parameters; the undocumented getValues was removed, so OwnProps(false) is an error.
  • OutputDebug takes only Text. Ks.OutputDebugLine still takes the clear flag.
  • StartsWith and EndsWith take CaseSense, matching InStr, in place of the inverted-sense ignoreCase.
  • A CLR call returning a .NET Task hands back a Task object rather than a raw CLR value. Its Result is a snapshot which never waits, where Task.Result used to block the whole thread and freeze the message loop; Wait() returns whether it finished before the timeout, including failure or cancellation; and the raw CLR surface moved behind Task.ToClr(). Use Await to wait for a value.
  • A script function handed to a CLR API as a callback no longer runs on whatever thread the CLR chose. It is marshalled onto the script thread that created it and runs in its own thread, which is what gives it correct A_* values, safe GUI access and an error that is reported rather than fatal. A callback invoked from a foreign thread is therefore asynchronous and cannot return a value to the CLR caller; one invoked synchronously, such as a comparer or predicate, is unaffected.
  • A comma written immediately after the name that starts a statement is a syntax error, as in AutoHotkey: MsgBox, "a" reports function calls require a space or "(" — use a comma only between parameters. The v1 command form previously compiled to a comma sequence which read MsgBox as a variable and called nothing at all. A space before the comma is unaffected and still omits the first argument (MsgBox , "a"), and a name that indexes or calls before the comma keeps its comma sequence (arr[1], x := 4 and fn(), x := 4). The same applies to a bare variable (x, y := 2), to a member chain (obj.Method, 1), and to Goto and For, where the comma was previously ignored — For, k, v in m silently built a three-variable loop whose first variable was blank.
  • Only the leftmost target of a class field declaration becomes a property. Every other name assigned in the initializer is a local of the generated __Init, as in AutoHotkey, so a := b := "asdf" gives the instance an a and no b. Such a name previously resolved to the module variable, which meant a class initializer overwrote a same-named global, kept its value between instantiations, and was visible to other classes and to __New. A name that is only read still reaches the global, and static fields have their own scope in static __Init.
  • A zero-argument call statement continued by a leading comma on the next line calls the function with its first argument omitted, because AutoHotkey separates the joined lines with a space. It previously formed a comma sequence, which evaluated the name without calling it.
  • A DefineProp descriptor is validated before the property is touched, as in AutoHotkey: it must name at least one of Value, Get, Set and Call; Value cannot accompany the other three; and each of Get, Set and Call must hold a function object. Each failure is a ValueError naming the descriptor, where {value: 1, call: fn} previously defined the Call and silently dropped the Value, and an empty descriptor ended the process with an uncatchable .NET exception. Keys other than those four are still ignored, so {value: 1, note: "x"} remains valid. The four are read from the descriptor's own value properties, which is where AutoHotkey reads them: a slot inherited from a prototype is invisible, so is a dynamic own property, and a Map is read through its own properties rather than its items — so Map("value", 7) is rejected where it previously defined the property.
  • Base64Encode and Base64Decode became Base64.Encode and Base64.Decode, matching Json and the new Url. Import the class rather than the two functions: #Import "Ks" { Base64 }.
  • Download pumps while it waits, as AutoHotkey's does, so timers, hotkeys and the GUI stay alive during a download and the wait is an interruption point. It also streams to the file instead of buffering the whole resource in memory, so the download's size is no longer the script's memory.

New

  • The Http class sends HTTP requests on every platform, where the AutoHotkey idiom ComObject("WinHttp.WinHttpRequest.5.1") is Windows-only. Static shortcuts — Http.Get, Http.Post, Http.Request — share one stateless client, and Http(Options) creates a session carrying default headers, credentials and a cookie jar. Each method has an Async twin returning a Task. A non-2xx status is an answer rather than an error; Http.Response carries the status, merged headers, decoded text, raw bytes and a Json() shortcut. OnData streams the body as it arrives and stops the transfer when it returns a non-zero Integer.
  • The Url class percent-encodes and decodes text for URLs and form bodies, so a query string is "?q=" Url.Encode(Query).
  • The #App directive declares final application facts in one or more object-literal blocks, with repeated keys applied in source order so the last value wins: assembly identity and metadata, relative-path Icon (the default tray, window and compiled-executable icon, with no startup flash), GuiTheme (applied before runtime windows and dialogs, including auto-execute errors; compile-time errors are unaffected), ConsoleApp, HookMutexName and relative-path embedded Files. The finished manifest is embedded in the compiled assembly as the Keysharp.App.json resource and applied by the runtime before it creates chrome; it stores canonical logical asset paths, never resolved build-machine paths.
  • The App class reports the running application: its assembly identity and metadata, the command line the process was launched with, and the reason and status of an exit in progress. The last two are readable from a __Delete, a timer or a library, which receive none of an OnExit callback's parameters. Every member is read-only, and a key which was never declared reads as an empty string rather than raising.
  • The Keysharp-only #TrayIcon directive selects and embeds a startup tray icon at compile time. #TrayIcon FileName [, IconNumber] selects an icon group, numeric resource ID or named managed resource from a main-script-relative file; bare #TrayIcon restores the default. It and #NoTrayIcon are applied in source order, so the later directive determines whether the startup icon is visible.
  • FileInstall is now supported: it extracts a file embedded via #App { Files: [...] }. When no matching payload is embedded — including in source mode — it copies the live file named by Source. The destination directory must already exist in either mode.
  • The Dash: a launcher for creating a script from a template, running an existing one, and opening the bundled tools and demos. It ships as Keysharp.cks at the install root, so the Start-menu entry, Keysharp.app, the Linux desktop entry and a bare keysharp all reach it through the existing default-script search. A script of your own named after the executable still takes precedence.
  • --compile asm accepts several scripts in one command, each compiled to a .cks beside its own source. They share one warm parser and compiler, so this is considerably faster than one command per script. --dest and --transpile each name a single output and so take a single script.
  • Named arguments: an argument can name the parameter it is for, as in SubStr(s, StartingPos: 2). A name matching no parameter is an error, reported before the script runs where it can be (#Warn NamedArg). NamedArgs carries such a call's names at run time.
  • Func.Params describes a function's parameters: name, position, whether optional, ByRef or variadic, and any default.
  • Await and the Task class let a script use an asynchronous .NET API. Await blocks the calling thread while pumping everything else; Then handles success and optionally failure, and recursively flattens asynchronous work returned by either callback. Status reports "Pending", "Succeeded", "Failed" or "Canceled" as one consistent snapshot, with IsPending/IsSucceeded/IsFailed/IsCanceled for a single question. WhenAny transfers the first outcome, Task.Create turns a callback-shaped event into a task, and custom objects can expose work through __Await().
  • A RealThread worker exposes its two completions as tasks: Task carries the entry function's value or error and settles the moment the body leaves, and Terminated completes when the operating-system thread is gone, with IsAlive as the short form of the second question. Post hands back the Task carrying the queued work's result, so cross-thread work composes with Then and the combinators and its failure reaches the caller. Exit returns the termination task, so Await(worker.Exit()) stops a worker and waits for it. Send is the synchronous form and fails fast where Post defers.
  • Support for keys which send a combination rather than one keystroke, such as the Copilot and Office keys. Copilot is an alias in static hotkey and remap declarations for the combination the key emits; it is not a runtime key name.
  • Both terms of a custom combination may carry modifiers, as in <^a & b::.
  • The Crypt class hashes values and files, encrypts and decrypts with AES, derives keys with PBKDF2 and returns secure random values.
  • The Clipboard class reads and writes the clipboard as text, images, files, HTML, RTF or a native format, and can wait or watch for changes.
  • The Monitor class describes one display: its geometry, identity, scale, brightness and DDC/CI controls, with OnChange for configuration changes.
  • The Audio class plays sounds from a file or from memory. An Audio.Output holds one stream, prepares its clips ahead of time and overlaps several sounds at once, and every play returns an Audio.Playback whose volume, pan, position, loop and mute can be changed while the sound runs. The same class enumerates and operates devices by exact identity, controls other applications' sessions, observes a level through an Audio.Meter, records from a microphone or from what an output device is playing, and reports device arrivals, removals and default changes through OnDeviceChange. Application sessions and endpoint metering are unsupported on macOS, and the Linux and macOS backends are unverified. The Sound functions keep their own device selector and semantics.
  • The Lock class guards code shared between real threads. Acquire takes a timeout and reports whether it got the lock, and a lock can be held across several statements rather than around one call.
  • Thread is a class as well as a function; an instance describes one script thread and can end it. A_Thread is the current one, A_RealThread the real thread it runs on.
  • The Boolean type names a truth value, so a boolean can be told apart from the Integer 1 or 0 in a type test.
  • The Font class carries a font as a value object, plus the platform's own interface, emoji and monospace families. Gui and each control expose it as a property.
  • The #CSharp directive embeds C# compiled into the script's own assembly: an inline block, a named file, or a <Library> resolved through the Lib folders.
  • NuGet packages, through the #Package directive at compile time or Clr.LoadPackage at run time.
  • The #App ConsoleApp key builds a compiled script as a console application.
  • The #Warning directive reports a message at compile time without failing the build, as the sibling of #Error.
  • ComponentAvailable reports whether the parser or compiler component is installed and loadable.
  • Gui.OnMessage and Gui.Control.OnMessage register a callback for a window message. Window messages are a Win32 concept, so the registration never fires on Linux and macOS.
  • SoundPlay and SoundBeep play on Linux and macOS as well as Windows. Which formats work on Linux depends on the installed player.
  • WinEvent.CaretMove fires when the text caret moves, reporting its rectangle in A_EventInfo. Every event type is delivered on all platforms.
  • The WebView control shows a webpage and lets a script drive it: Url, DocumentTitle, history through GoBack/GoForward, Stop, Reload, ExecuteScript and its asynchronous form, LoadHtml and ShowPrintDialog. The page drives the script back through MessageReceived, and five other events report navigation, one of which can cancel it. The engine is not shipped with Keysharp, so what it renders differs by platform: WebKit through Eto off Windows, and on Windows either Edge, when a script asks for WebView2 with #Package, or Internet Explorer when it does not. Engine reports which one a control got.
  • The RichEdit control is a formatted-text editor a script can drive a character at a time, which is how syntax highlighting is done. SetFormat and GetFormat give a range a font, a text color and a background, leaving alone anything the options do not name; BeginUpdate/EndUpdate wrap a whole re-highlight into one repaint. Alongside them are the selection and caret (SelectionStart, SelectionLength, CurrentLine, CurrentCol, Select, SelectAll, ScrollCaret, FirstVisibleLine), lines and positions (GetLine, LineLength, LineFromPos, PosFromLine, PosFromPoint, PointFromPos), editing (Append, Replace, Find, Cut, Copy, Paste, Undo, Redo), paragraph formatting, LoadFile/SaveFile, and the Change, SelectionChange and LinkClick events. Every position is 1-based and indexes the same text Value returns. Not all of it is available off Windows.
  • Overlay.OnEvent registers mouse handlers on an overlay which is not click-through.
  • The Taskbar class draws a badge and a progress bar on a window's taskbar button, launcher icon or dock tile.
  • Gui.SetIcon and the Icon property give one window an icon of its own, in place of the tray icon it was created with.
  • Gui +DPIResize re-lays a window out when it moves to a display with a different DPI, and +Round rounds its corners. The Menu item options Radio, Right, RTL, Break and BarBreak are supported.
  • Json.Encode takes an Indent option, and Json.Decode a CaseSense option for the Maps it produces.
  • DirCopy extracts .zip, .tar, .tar.gz and .tgz archives, and decompresses a plain .gz.
  • Array.Remove returns whether it removed anything, and Contains, IndexOf and Remove search for an element with no value when Value is omitted.
  • File.Read takes an optional character count; omitting it reads the rest of the stream.
  • FileEncoding and its siblings accept any encoding .NET recognizes, such as windows-1252.
  • #Import accepts a relative path. Module globals are implicitly available for wildcard import, bare imports and aliases bind module objects, and imported names are forwarded only by #Import Export; standalone Export declarations and default exports no longer exist. A backslash works as a path separator on every platform in #Include, #Import and #CSharp.
  • Clr accepts an Integer where a .NET enum is expected, including undeclared flag combinations.
  • Built-in objects which stand in front of a CLR object expose it through a uniform ToClr() method returning an ordinary Clr object: Task, Gui, Gui.Control, Menu and Image. Map is a CLR IDictionary<object, object> and Array an IList, so a CLR API declaring one accepts them directly, and their ToClr() exposes their full CLR surface late-bound. Inline C# holding a Clr wrapper reads the raw object from its Native property.
  • A_ProcessArch and A_OSArch report CPU architecture. Interop code should branch on these rather than A_PtrSize, which cannot tell X64 and ARM64 apart.
  • The compatibility target moved to v2.1-alpha.32, adding Gui.FontHandle to the compatibility contract. The property is not yet implemented by Keysharp. The preceding alpha.30 update in this release added typed signatures for CallbackCreate, ObjSetBase, the numeric type classes and further struct members.
  • Send {Click X Y Count} moves the pointer once before repeating the click. Successful output operations now store a blank value when no result exists, and a ListView column-header ContextMenu event reports Item as 0.
  • Ks.FileCreateTemp creates an empty temporary file and returns its path.

Platform

  • Windows: ARM64 builds, and a WiX-based installer.
  • Linux: the optional keysharp-input component provides global input hooks and keyboard/mouse synthesis; the optional keysharp-desktop component provides authorized capture and compositor-backed window, pointer and clipboard integration on X11 and Wayland. A script's own Wayland windows are placed and reported under the handle the script holds, so window and control geometry resolve correctly. Overlays receive mouse input on KWin and wlroots directly; GNOME and Cinnamon use a positioned client window for interactive overlays.
  • Linux: ComObject addresses a D-Bus service, calling its methods and properties by name through introspection, with ComObjConnect for signals, ComObjActive and ComObjGet for a service already on the bus, ComObjQuery to select an interface, and ComValue to state a D-Bus type where introspection cannot supply one. ComCall, ObjAddRef, ObjRelease, ComObjValue, ComObjFlags and ComObjFromPtr throw, because they depend on COM machinery D-Bus does not have. See Interprocess automation with ComObject.
  • macOS: ComObject addresses a scriptable application through Apple Events, resolving its commands, properties and elements by name from the application's scripting definition, with ComObjQuery to select a suite and ComValue to state a descriptor type. A command's first unnamed argument is its direct parameter and the rest are passed by name; controlling an application requires Automation permission. The same functions that throw on Linux throw here, for the same reason. See Interprocess automation with ComObject.
  • macOS: osx-x64 builds for Intel Macs alongside osx-arm64. macOS 15 or later is required.
  • Linux and macOS: the About dialog, and the status bar reporting which part was clicked.
  • Linux and macOS: A_GuiTheme applies Classic, System and Dark process-wide through Eto; System follows later operating-system theme changes.

Fixes and Performance

Send restoring stale modifiers in SendEvent mode, #Warn reporting the wrong line in an included file, #Import creating a setter for a read-only property, overriding a built-in class's __Enum, continuation sections, switch and Loop Files condition parsing, and a leading comma in a function call statement. A_MyDocuments, A_Desktop and the A_*Common folders resolve correctly. GUI fixes cover addressing a control by ClassNN, xs/ys anchoring in Tab3 pages, measuring a control created hidden, and a checkbox reporting its own state. A fat-arrow function reads a property exactly as a block-bodied one does; a call or an index in an arrow body still propagates an unset result. A script read from standard input resolves #Include against the working directory, which is what A_ScriptDir reports for it, and a byte-order mark at the head of such a script is not read as code. A built-in module's own name is reached only through #Import, as in AutoHotkey: Ks and Ahk are no longer global names. A class nested in another class is named by its full dotted path, as in AutoHotkey: Type and Prototype.__Class report Gui.Text for a text control, Clr.ManagedType, and Outer.Inner for a script's own nested class, each of which reported only the short name. Type reads that name from the base chain for every object, so an instance of a class which declares no fields is named by its class rather than by the internal type behind it. Such a class is reached only through the class which declares it, so Audio.%"Device"% is the dynamic form and the bare %"Device"% is an undefined name. The right operand of is must be a class, and anything else throws a TypeError reading Expected a Class but got a String, where a string or number was read as a value whose class was tested — x is "Array" asked whether x was a String. A dynamic reference which resolves to the class itself still works: x is %"Array"%. #HotIf criteria use a cheaper executor, and script processing is split into optional components so a deployment can omit the compiler.

Reading a property walks past an own property which cannot produce one — a setter without a getter, or a Call where something further up the chain has a value — so an inherited value, method or __Get is reached as it is in AutoHotkey, and a setter is never returned as a method. A name nothing in the chain has raises a PropertyError naming the value's type, where it previously raised the more general UnsetError; PropertyError is an UnsetError, so an existing catch UnsetError is unaffected. ObjHasOwnProp handed a string or number raises a TypeError rather than ending the process.

A number keeps a trailing . when what follows it cannot begin a member name, so 1. is the float 1.0 and the operand beside it concatenates — 1. 2 is "1.02", matching AutoHotkey — while 1.Foo and 1 .2 stay member accesses on the integer. An inline block comment is whitespace to every decision that looks backwards: a :: inside one is comment text rather than a hotkey separator, where a line such as x := 1 /* a :: b */ previously failed to compile, and a comment before a . leaves it a member access. A class field initializer needing a temporary, such as x := (this.arr[1] += 5), compiles.

Breaking Changes

  • ImageCapture() was removed. Use the Image class instead.
  • Linux input requires the privileged evdev/uinput service; the SharpHook and X11 fallbacks were removed. See Platform Support.
  • A_ScaledScreenDPI was renamed to A_ScreenScale.
  • A_OSType now returns WINDOWS, OSX or LINUX.
  • A_LineFile in the main file resolves to the main script's full path, as A_ScriptFullPath does.
  • #Import inside a function or class body binds to that scope, and an unknown import throws.
  • Reserved words can no longer be used as variable names.
  • Invalid Gui options now throw instead of being ignored.

New

  • Image captures, loads, creates, draws, transforms, searches and manipulates pixels before saving. It replaces ImageCapture().
  • Overlay is an always-on-top, click-through canvas using the same drawing primitives as Image. It now backs Highlight and ToolTip on Linux and macOS.
  • WinEvent subscribes to window events across platforms: Active, Exist, NotExist, Move, Minimize, Restore and TitleChange.
  • Thread identity, and Exit targeting a thread other than the current one.
  • OnMouseDown, OnMouseUp and OnMouseMove on InputHook.
  • Fully cross-platform monitor functions, plus MonitorGetScale and MonitorFromPoint in the KS module.
  • Gui +ClickThrough and +AutoScroll options.
  • An *Dir scan-direction option for ImageSearch.
  • An OCR library (OCR.ks) with a pluggable engine, and demo scripts including ClipboardHistory, InputHUD, OCRSnip, Shell, WindowGrab and WindowTiler.

Platform

  • Linux: input channels use the evdev/uinput service, with multi-user handling, per-script permissions, Unicode sending and mouse buttons.
  • Wayland: overlays, clipboard and window manipulation through KWin scripting and Keysharp shell extensions for GNOME (including v48 and later) and Cinnamon.
  • macOS: the hook and sender were revamped on CGEventTap and the key sender is now functional. Binaries are signed, and releases include DMG and PKG packages with SHA256 checksums.

Fixes and Performance

Release-mode stack traces for C# exceptions, OnExit teardown, script exit when the last window closes, thread priority handling and DLL path normalization. Parser fixes for #Include, static variables, dereferences and remap syntax. Regular-expression pattern caching, font caching, cheaper per-call thread setup and faster keyboard-layout queries.

0.0.0.15

Released 22 June 2026. This release made Keysharp cross-platform across Windows, Linux and macOS.

  • macOS support: window management, the keyboard and mouse hook and sender, sound and drive functions, App Switcher integration and native Command-key handling, plus AxSpy, an accessibility inspector.
  • Linux: the inputd input daemon, .deb packaging with automatic .NET 10 installation, Unicode character sending and Keyview syntax highlighting.
  • New parser: a hand-written parser replaced ANTLR4, which is faster and less ambiguous.
  • AutoHotkey v2.1 features: the v2.0 and v2.1 compatibility modes, structs with #StructPack, the #Import directive, PropRef, the !~= operator and ahk_opt.
  • Scheduler: the timer and event scheduler was reworked, fixing timer livelock and timers not firing inside hotkey callbacks.
  • Cross-platform GUI on Eto: DPI scaling, dialog theming and hyperlink labels.
  • The hook and sender were brought current with AutoHotkey 2.0.26.
